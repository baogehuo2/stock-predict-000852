# Buy 2.0 多时点信号评估框架

## 目标

Buy 2.0 不再只把信号理解为“收盘后生成、次日参考”的单一日频结果，而是按真实交易决策时点拆分为盘前、盘中、尾盘和盘后四类信号。每一类信号都必须明确数据可得性、生成时间、执行时间、标签定义和样本外验证方式，避免把收盘后才能知道的数据用于盘前或盘中判断。

## 总原则

1. 所有评估必须遵守因果数据边界：某一时点不可使用该时点之后才可知的数据。
2. 同一个模型版本可以共享底层数据和部分特征，但不同决策时点必须有独立的特征口径和评估口径。
3. Buy 2.0 的核心评估不只看总体 precision，还要按决策时点分别看 signal count、coverage、positive return rate、average future return、median future return、年度稳定性和相对同期天然基线提升。
4. 新闻事件必须区分发布时间和归属交易时点：昨日盘后新闻可以进入今日盘前评估，今日盘中新闻只能进入其之后的盘中或尾盘评估。
5. 1.0 的 `buy-signal-v1.0` 保持封版，2.0 的多时点评估不得改写 1.0 信号口径。

## 四类决策时点

### 1. 盘前模型

用途：在今日开盘前判断今日是否存在买入必要。

可用数据：

- 截至昨日收盘的日线行情、成交量和技术指标。
- 昨日收盘后发布的新闻事件。
- 今日开盘前发布的新闻事件。
- 已知的宏观、政策、日历和外部市场信息。

不可用数据：

- 今日开盘后的价格、成交量、分时走势。
- 今日收盘后才能形成的完整日线技术指标。

建议输出：

- `preopen_buy_score`
- `preopen_direction`
- `preopen_risk_level`
- `signal_trade_date`
- `execute_date`
- `data_cutoff_time`

评估口径：

- 以今日开盘或开盘后固定窗口作为可执行价格参考。
- 标签应对应今日买入后未来 N 个交易日收益，而不是昨日收盘后的未来收益。
- 新闻事件按发布时间映射到盘前窗口，不能简单按自然日期聚合。

### 2. 盘中事件模型

用途：交易时间内每隔固定频率重新吸收新闻、舆情和盘中行情，动态调整机会与风险评分。

建议频率：

- 默认每 1 小时评估一次。
- 可扩展为重大新闻触发式评估。

可用数据：

- 截至当前评估时间的盘中价格、成交量、涨跌幅、相对指数表现。
- 当前评估时间以前发布的新闻事件。
- 当前评估时间以前的舆情或公告信息。
- 上一交易日及更早的完整日线特征。

不可用数据：

- 当前评估时间之后的价格、成交量和新闻。
- 当日收盘后才可确认的完整日线特征。

建议输出：

- `intraday_event_score`
- `intraday_buy_score`
- `intraday_risk_score`
- `decision_time`
- `data_cutoff_time`
- `action_hint`: `hold_neutral` / `upgrade_watch` / `downgrade_risk` / `allow_buy`

评估口径：

- 按具体评估时间切片，例如 10:30、11:30、13:30、14:30。
- 每个切片只能使用该时间点以前的数据。
- 对比基线应包含上一日收盘信号、盘前信号和简单盘中动量/回撤规则。

### 3. 尾盘决策模型

用途：在 14:50 左右使用接近完整的当日 K 线和盘中信息，判断是否需要在收盘前买入。

可用数据：

- 截至 14:50 的当日价格、成交量、振幅、相对强弱和近似日线特征。
- 截至 14:50 的盘中新闻事件。
- 昨日收盘及以前的完整日线特征。

不可用数据：

- 14:50 之后发布的新闻。
- 15:00 之后才能确认的数据。
- 当日收盘价如果尚未产生，不得直接使用正式收盘指标替代。

建议输出：

- `preclose_buy_score`
- `preclose_direction`
- `preclose_confidence`
- `preclose_data_cutoff_time`

评估口径：

- 执行价可用 14:50 之后可成交价格或收盘价近似，但必须在评估报告中固定一种口径。
- 特征应使用“截至 14:50 的近似日线”，不能与正式收盘日线混淆。
- 应单独比较尾盘模型相对盘前模型是否增加有效信息。

### 4. 盘后复盘模型

用途：收盘后生成正式日频信号，供下一交易日盘前参考。

当前 1.0 已覆盖此类能力：

- T 日收盘后生成 `trade_date=T` 的 Buy 信号。
- T+1 日盘前读取该信号作为候选执行依据。

Buy 2.0 中的盘后模型应继续作为基准信号层，但需要明确：

- 它不是 T+1 当日盘前模型，只是 T 日收盘后的正式信号。
- 它可以作为 T+1 盘前模型的基础输入之一。
- T 日盘后新闻如果在收盘后才发布，应进入 T+1 盘前评估，而不是污染 T 日收盘模型。

## 新闻事件归属规则

Buy 2.0 必须新增事件时间归属逻辑，至少区分：

1. `preopen`: 开盘前事件。
2. `intraday`: 交易时段事件。
3. `preclose`: 尾盘评估前事件。
4. `postclose`: 收盘后事件。

建议规则：

- 昨日 `postclose` 事件进入今日 `preopen` 特征。
- 今日 `preopen` 事件进入今日 `preopen`、`intraday` 和 `preclose` 特征。
- 今日 `intraday` 事件只进入发布后对应的盘中切片和尾盘特征。
- 今日 `postclose` 事件进入下一交易日 `preopen` 特征。

## 2.0 评估要求

每一个候选模型或特征组都必须分别回答：

1. 它改善的是盘前、盘中、尾盘还是盘后信号？
2. 该信号在真实决策时点是否可获得所有输入数据？
3. 它相对 1.0 盘后基准信号是否有增量价值？
4. 它是否只提升某一年，还是跨年度稳定？
5. 它是否增加过多信号、稀释 precision 或提高回撤风险？

核心指标：

- `signal_count`
- `coverage`
- `precision`
- `positive_ret_rate`
- `avg_future_ret`
- `median_future_ret`
- `yearly_stability`
- `baseline_lift`
- `overlap_with_v1_signal`
- `incremental_signal_quality`

## 推荐开发顺序

1. 先保留 1.0 盘后信号作为基准层。
2. 增加盘前复核模型：只处理昨日盘后新闻和今日盘前新闻，判断是否维持、降级或增强 1.0 信号。
3. 再增加尾盘决策评估：使用 14:50 近似日线和盘中事件，评估是否比盘前判断更有效。
4. 最后增加盘中每小时事件模型，因为它对数据实时性、新闻时间戳和行情粒度要求最高。

## 与 1.0 的关系

- 1.0 是冻结的日频盘后基准模型。
- 2.0 可以使用 1.0 信号作为输入或对照，但不能修改 1.0 模型文件、特征清单和信号表口径。
- 2.0 的版本、特征清单、数据库输出和报告必须独立命名。
