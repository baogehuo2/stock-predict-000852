# 入口拆分总规

## 目的

当前项目已经进入多分支并行阶段。为了避免 `main_daily_run.py` 互相覆盖、互相丢入口、互相引入高冲突，现阶段采用“分支各自入口、公共采集可复用、特征与样本按分支独立”的拆分原则。

## 总原则

1. `main_daily_run.py` 不作为所有分支的统一总入口。
2. 每个分支保留自己的入口脚本。
3. 公共采集可以共用基础采集函数，但入口由各分支自己维护。
4. 特征构建、样本构建、训练、预测、报告全部按分支独立。
5. 如果某个能力会影响别的分支默认流程，不要直接并回 `main_daily_run.py`，先拆成分支入口。

## 适用范围

本规则适用于以下 worktree / 分支：

- `main`
- `feature/data-collectors`
- `feature/data-collectors-clean`
- `feature/buy-signal-research`
- `feature/bottom-fishing-v1`
- `codex/buy-signal-dashboard`
- `codex/turning-label-tool-clean`
- `codex/weekly-turning-final`
- `分析`
- 以及后续新建的专题分支

## 入口职责边界

- 主干样本
- 主线训练
- 主线预测
- 主线报告

不建议保留：

- 专题分析入口
- 底部研究入口
- 看板入口
- 专题采集入口
- 临时试验入口

## 拆分方式

每个分支都按下面方式处理：

1. 先保留本分支真正需要的入口。
2. 再删掉来自其他分支的默认调度内容。
3. 如果发现某个能力是共用函数，就抽函数，不抽总入口。
4. 如果一个步骤只对本分支有效，就让它留在本分支入口里。
5. 不要为了“方便统一”把所有分支都塞进同一个 `main_daily_run.py`。

## 合并规则

1. 先确保分支自己的入口能独立运行。
2. 再合并到 `main`。
3. 合并时如果 `main_daily_run.py` 发生冲突，优先保留主干共用流程。
4. 分支特有流程不要直接覆盖主干入口。
5. 如果确实需要长期复用，先抽公共函数，再在各自分支入口里调用。

## 验收标准

每个分支拆完后，至少满足：

- `git status --short` 干净或仅剩可解释的本地改动
- 本分支入口可以单独执行
- `main_daily_run.py` 不再包含其他分支的私有流程
- 没有把别的分支的 step 名称误删
- 没有把本分支默认流程覆盖成别的分支默认流程

## 给各分支 Codex 的执行指令

建议直接按下面顺序做：

1. 先看当前分支的 `git status --short`
2. 找出本分支自己的入口文件
3. 只整理本分支要保留的 step
4. 删除或移出别的分支才需要的入口逻辑
5. 检查入口脚本能否单独运行
6. 最后只提交本分支自己的改动
