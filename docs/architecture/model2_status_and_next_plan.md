# Model 2.0 当前状态与下一步计划

本文汇总截至当前为止 Model 2.0 的数据使用、建模结果、有效结论和下一步计划。结论基于 2021 至 2026-06-10 的滚动验证。

## 一句话结论

Model 2.0 目前还不能替换 1.0。

当前最好的模式不是“把更多数据塞进一个大模型”，而是：

- 1.0 继续作为普通买入信号。
- 政治事件作为高置信度增强层。
- 不降低普通买入阈值来追求更多信号。
- 后续重点补“事件方向、政策强弱、情绪解释”，而不是继续堆原始行情和日历窗口。

## 当前正式基线

当前正式模型仍是：

- 模型版本：`buy-signal-v1.0`
- 特征版本：`buy-features-v1.0`
- 周期：7 日
- 普通买入阈值：`buy_proba >= 0.60`
- 门控：牛市硬门控

滚动验证结果：

| 信号 | 信号数 | Precision | 实际上涨率 | 平均未来7日收益 |
| --- | ---: | ---: | ---: | ---: |
| 1.0 普通信号 | 36 | 69.44% | 72.22% | 1.7693% |

这个模型信号不多，但有统计价值，暂时不应推翻。

## 政治事件增强层

政治事件增强层是目前 2.0 最有价值的部分。

当前三档信号：

| 层级 | 规则 | 信号数 | Precision | 实际上涨率 | 平均未来7日收益 |
| --- | --- | ---: | ---: | ---: | ---: |
| `long` | 1.0 `buy_proba >= 0.60` | 36 | 69.44% | 72.22% | 1.7693% |
| `strong_long` | 全政治事件 `political_proba >= 0.70` | 18 | 77.78% | 88.89% | 3.2336% |
| `very_strong_long` | CEWC `cewc_proba >= 0.75` | 17 | 82.35% | 94.12% | 3.0150% |

人话解释：

- 1.0 是日常普通信号。
- 政治事件增强层是更少、更精的信号。
- CEWC 特强信号更稀疏，但命中率更高。

当前建议采用：

| 输出 | 含义 |
| --- | --- |
| `neutral` | 不买 |
| `long` | 普通买入 |
| `strong_long` | 政治事件增强买入 |
| `very_strong_long` | CEWC 特强买入 |

优先级：

`very_strong_long > strong_long > long > neutral`

## 1.0 概率分层结论

已经测试过是否可以降低 1.0 阈值来增加信号。

结果不支持降低阈值。

| 模式 | 信号数 | Precision | 平均未来7日收益 | 最差未来7日收益 |
| --- | ---: | ---: | ---: | ---: |
| 0.50-0.60 | 31 | 48.39% | 0.3250% | -11.2282% |
| 0.55-0.60 | 18 | 55.56% | 0.5053% | -11.2282% |
| >=0.60 | 36 | 69.44% | 1.7693% | -7.4679% |
| 0.70-0.75 | 10 | 80.00% | 1.8590% | -2.0082% |

结论：

- 不建议增加 `watch_long = buy_proba >= 0.50`。
- 不建议增加 `light_long = buy_proba >= 0.55`。
- 低阈值会明显引入噪音和大亏样本。
- 提高覆盖率不能靠放低 1.0 阈值，应靠外部增强层。

## 当前问题

Model 2.0 目前最大问题不是没有价值，而是：

1. 有效信号少。
2. 原始数据直接入模效果差。
3. 高维特征容易稀释 1.0 的有效结构。
4. 宏观和事件数据没有方向解释，只靠日期窗口不够。
5. 政治事件已形成候选固定模型包，但还没有升级为正式 2.0 模型。

## 下一步总体思路

下一步不要继续做“大杂烩式加特征”。

应该改成：

1. 先做事件解释。
2. 再做信号增强。
3. 最后做正式模型固化。

也就是说，2.0 的核心不是“更多字段”，而是“更懂事件含义”。

## 下一步数据采集计划

### 1. 政策事件方向与强度

优先级最高。

需要采集或构建：

- 中央经济工作会议全文或权威通稿
- 政治局会议通稿
- 两会政府工作报告
- 重要金融委、国常会、证监会、央行、财政部政策通稿
- 与资本市场、小盘成长、流动性、融资、科技产业相关的政策文本

需要落库字段建议：

- `event_id`
- `event_date`
- `publish_time`
- `event_type`
- `source_org`
- `source_title`
- `source_url`
- `raw_text`
- `policy_direction`
- `policy_strength`
- `liquidity_tone`
- `capital_market_tone`
- `small_cap_tone`
- `tech_growth_tone`
- `risk_warning_tone`
- `available_time`

其中方向类字段可以先由规则或 LLM 离线抽取，不要在建模侧临时调用 LLM。

### 2. 新闻事件方向

当前新闻/事件如果只是数量和热度，不够。

下一步应补：

- 利好/利空方向
- 影响对象：小盘、成长、科技、流动性、监管、风险偏好
- 事件强度
- 持续天数
- 是否属于“利好兑现”
- 是否属于“风险连续累积”

建议字段：

- `news_date`
- `publish_time`
- `source`
- `title`
- `url`
- `event_category`
- `impact_direction`
- `impact_strength`
- `target_asset`
- `small_cap_relevance`
- `liquidity_relevance`
- `risk_relevance`
- `is_policy_event`
- `is_risk_event`
- `available_time`

### 3. 股吧和社交情绪

股吧可以继续暂缓，但如果要做 2.0 覆盖率提升，最终需要它。

不要只做情绪均值，建议采：

- 发帖量
- 评论量
- 阅读量
- 情绪均值
- 情绪分歧
- 极端乐观比例
- 极端悲观比例
- 过热状态
- 情绪从冷到热的变化
- 情绪高位回落

注意：

- 股吧情绪更适合作为风险过滤和过热过滤，不一定适合作为买入增强。
- `use_guba_sentiment` 当前仍保持 `false`，正式启用前要单独验证。

### 4. 宏观数据解释层

宏观 actual 直接入模效果一般，下一步要把它转成“超预期”和“政策含义”。

建议补：

- 是否超预期
- 超预期方向
- 超预期幅度
- 对流动性的含义
- 对风险偏好的含义
- 对小盘成长的含义
- 连续改善/连续恶化次数

例如：

- 社融超预期且连续改善：偏利好流动性
- CPI/PPI 低位但改善：可能利好宽松预期
- 美国利率上行超预期：可能压制成长风格

### 5. 海外风险事件

海外行情本身直接入模效果不好。

下一步应采事件，而不是只采价格：

- FOMC 决议方向
- 美联储讲话鹰鸽
- 美国 CPI/非农超预期方向
- 地缘政治风险升级/缓和
- 原油冲击事件
- 美债利率快速上行事件

这些也应转成事件方向和强度。

## 下一步建模方法调整

### 1. 从“大模型直接吃全部特征”改成“主模型 + 增强模块”

当前建议结构：

```text
1.0 技术/市场主模型
        |
        +-- 普通 long

政治事件增强模型
        |
        +-- strong_long / very_strong_long

风险过滤模型
        |
        +-- 降级或取消信号
```

不要把所有字段全塞进一个 LightGBM。

### 2. 增强模型单独训练、单独阈值

政治事件已经证明适合独立阈值。

后续应把增强模型固化为正式模型包：

- `models/buy_lgbm_political_strong_v2_7d.joblib`
- `models/buy_lgbm_cewc_very_strong_v2_7d.joblib`

然后每日预测时加载固定模型，而不是运行时临时训练。

### 3. 做风险过滤，而不是只做买入增强

后续新增数据有一部分更适合过滤风险：

- 股吧过热
- 情绪分歧扩大
- 海外风险冲击
- 宏观负面连续累积
- 政策利好兑现

这些不一定提高买入信号数量，但可以减少错误信号。

建议新增：

- `risk_filter = true / false`
- `risk_reason`
- `signal_downgrade`

### 4. 做信号优先级，而不是只输出 long/neutral

建议最终输出：

| 字段 | 含义 |
| --- | --- |
| `direction` | `neutral / long / strong_long / very_strong_long` |
| `signal_strength` | `none / normal / strong / very_strong` |
| `base_buy_proba` | 1.0 概率 |
| `political_proba` | 政治事件增强概率 |
| `cewc_proba` | CEWC 增强概率 |
| `risk_score` | 风险过滤分 |
| `enhanced_reason` | 增强原因 |
| `risk_reason` | 风险原因 |

## 下一步执行顺序

### 第一步：固化政治事件增强模型

在当前建模分支做。

任务：

- 训练固定政治事件增强模型包：已完成
- 训练固定 CEWC 增强模型包：已完成
- 改造候选信号输出，不再运行时训练：已完成
- 用 2021-2026 滚动验证和最近样例确认一致性

验收：

- 能每天直接生成 `long / strong_long / very_strong_long`
- 不写入正式 1.0 表
- 结果与研究评估口径一致

已生成模型包：

- `models/buy_lgbm_political_strong_v2_7d.joblib`
- `models/buy_lgbm_cewc_very_strong_v2_7d.joblib`

后续如果第三批事件解释数据完成，再训练新的增强模型包版本。

### 第二步：采集分支补事件解释数据

在 `feature/data-collectors` 做。

给采集分支的任务说明：

```text
请新增 2.0 第三批数据采集：政策/新闻事件方向与强度解释层。

目标不是只采原文，而是形成可建模字段：
- 事件方向：利好/利空/中性
- 事件强度：1-5
- 小盘相关度
- 流动性相关度
- 科技成长相关度
- 风险偏好相关度
- 是否政策事件
- 是否风险事件
- available_time

优先覆盖：
- 中央经济工作会议
- 政治局会议
- 两会政府工作报告
- 证监会/央行/财政部/交易所重要政策
- 中证1000、小盘、成长、科技、流动性相关新闻

只做数据采集、清洗、入库和质量报告，不做建模。
```

### 第三步：建模分支做第三批消融

采集完成后回到当前分支。

任务：

- 构建事件方向特征
- 构建政策强度滚动特征
- 构建风险连续累积特征
- 重新测试：
  - 1.0 基线
  - 政治事件增强
  - 政策方向增强
  - 风险过滤
  - 增强 + 风险过滤组合

### 第四步：再考虑回测

目前仍不建议马上做完整回测。

原因：

- 2.0 信号层还在定型。
- 风险过滤还没做。
- 增强模型还没固化。

等完成：

- 固定模型包
- 稳定信号输出
- 风险过滤

再进入回测分支更合适。

## 当前不建议做的事

- 不建议把第一批和第二批所有特征合并成一个大模型。
- 不建议降低 1.0 阈值到 0.50 或 0.55。
- 不建议用宏观 actual 原值直接继续堆特征。
- 不建议马上做完整交易回测。
- 不建议启用股吧情绪进入正式模型。

## 当前建议做的事

- 保留 1.0 正式普通信号。
- 固化政治事件增强模型。
- 采集事件方向和政策强弱。
- 做风险过滤模块。
- 形成分层信号，而不是单一 long/neutral。
